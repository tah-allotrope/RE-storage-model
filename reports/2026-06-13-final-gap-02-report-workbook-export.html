Final Report · Sprint Synthesis

Download buttons for real artifacts

The web tool can now hand users the artifacts a financial-model platform is expected to produce. The model has shipped a polished HTML report and a branded Excel workbook for months — the dashboard let you download nothing but raw JSON. In three phases we exposed both: a Download HTML Report and a Download Excel Workbook button now appear next to the existing JSON button, re-running the model from the last submitted inputs and streaming the artifact back with the correct file type and filename. Shipped to main, fully tested, with the multi-scenario workbook deliberately deferred.

02 · Background & Objective

Why this mattered now

RE-Storage is benchmarked against NREL's REopt. REopt-style tools are expected to produce client-shareable artifacts — a printable summary and a structured workbook investors can drop into their own due-diligence stack. The model side of RE-Storage had both. The web side, despite shipping a verdict banner (GAP-01) the week prior, still forced users to copy KPI cards by hand or re-run the model in the CLI to get the artifact. The objective: close that gap so anyone with browser access to the tool can produce the same artifacts a developer could produce locally.

07 · Findings & Recommendation

What we found, what we advise

Findings

  • The largest gap was again presentation, not computation — both artifacts existed, only the URL surface was missing.
  • The source=json|excel form-field switch let one endpoint serve both run paths, halving the URL count and keeping the frontend simple.
  • Re-running the model in the export request (rather than caching the heavy DataFrames) is cheap (~2–10 s) and avoids coupling GAP-02 to Firestore/Storage (GAP-04).
  • Loading the xlsx response with openpyxl.load_workbook(BytesIO) in tests caught what a plain "is non-empty zip" assertion would miss — a workbook with the wrong sheets.

Test growth (TDD)

Recommendation: ship as-is. The single-run scope covers the 95% case (one PPA option, one topology). Treat the multi-scenario workbook (?full=true, requires run_all_scenarios) as a fast-follow only after measuring whether it fits inside the 300 s Cloud Function timeout on production fixtures.

09 · Risks / Open Questions

What to watch

  • Manual download UX outstanding: backend tests & frontend build pass, but the button → spinner → file-saved flow has not been exercised against a live backend. Do this before deploy (Step 1 above).
  • HTML response size: generate_report embeds matplotlib PNGs as base64; on long-lifetime projects the response can grow to several MB. Cloud Function Gen 1 caps responses at 10 MB; Gen 2 at 32 MB. firebase.json does not declare a generation explicitly — confirm Gen 2 at deploy, or add a chart-count / DPI gate if Gen 1 is the target.
  • Re-upload cost on Excel path: every export click resends the full .xlsx from the browser. Acceptable for MVP; document as a candidate for GAP-04 caching.
  • Default report title: the HTML <title> still says "Emivest Model Report" (hardcoded in html_report.py); the attachment filename uses the project slug, but the in-browser title is wrong for other projects. Cosmetic, not blocking.
  • Pre-existing mypy noise: all web handlers (run_excel, run_json, run_report, export_workbook) have Incompatible return value type (got tuple[Response, int]) errors. Systemic, not introduced by GAP-02. Treat as a separate typed-cleanup PR.
  • Not yet live: users benefit only once GAP-04 deploys the app for real.
